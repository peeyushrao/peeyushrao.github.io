## 2. What is the difference between an alert, a detection, and an incident?

Understanding the distinction between **alerts**, **detections**, and **incidents** is fundamental to effective SOC operations. These terms represent different levels of analysis and confidence in the security event lifecycle.

---

## High‑Level Definitions

- **Alert**: A raw signal indicating that a predefined condition or threshold was met.
- **Detection**: An alert that has been analyzed and classified as suspicious or malicious using logic, context, or analytics.
- **Incident**: A collection of one or more related detections that together represent a confirmed or likely security event requiring response.

In practice, SOCs may receive thousands of alerts daily, far fewer detections, and only a small number of incidents that warrant activation of an Incident Response Plan.

---

## Alert

An alert is the **earliest and noisiest** signal in the pipeline.

### Characteristics
- Generated automatically by a security control
- Triggered when a rule, threshold, or condition is met
- Lacks sufficient context to determine intent

### Example Triggers
- High volume of network traffic
- Failed login thresholds exceeded
- Process execution or network connection events

Alerts indicate **something happened**, not whether it is malicious.

---

## Detection

A detection is produced when alerts are enriched with **context, intelligence, or analytics** and identified as likely malicious.

### Characteristics
- Represents a security tool’s analytic decision
- Uses logic, behavior, or threat intelligence
- Provides confidence that activity aligns with attacker tactics

A detection answers the question: *Is this likely malicious behavior rather than noise?*

---

## Incident

An incident represents the **confirmation of an adverse security event**.

### Characteristics
- Composed of one or more related detections
- Indicates policy violation, compromise, or imminent threat
- Triggers coordinated response and containment actions

Incidents are what SOC Leads and Incident Response teams actively manage.

---

## Example Scenario: Failed Logins on a Critical Server

### 1. Alert
- The SIEM triggers an alert after **five failed login attempts within one minute**

### 2. Detection
- Analyst review shows:
  - Attempts targeting the `Administrator` account
  - Source IP is known malicious
- Classified as an **Initial Access** attempt

### 3. Incident
- One login attempt succeeds
- A new user account is created
- Persistence is achieved

At this stage, an **incident is declared** and response procedures are initiated.

## CrowdStrike Falcon Perspective

In **CrowdStrike Falcon**, alerts, detections, and incidents are explicitly separated and handled differently.

---

## Alert (Event / Signal)

### Description
- Raw telemetry from the Falcon sensor or integrated data sources

### Examples
- Process execution
- DLL load
- Network connection

### Visibility
- Event Search
- Host Timeline

Not all alerts require action.

---

## Detection

### Description
- Falcon analytic determination that suspicious behavior occurred

### Generated By
- Indicators of Attack (IOAs)
- Behavioral Machine Learning
- Cloud analytics

### Attributes
- Severity
- MITRE tactic and technique
- Process tree context

### Example
- **Suspicious DLL Load via Unsigned DLL** detection

---

## Incident

### Description
- Falcon correlation of multiple detections into a single investigation
- Represents coordinated adversary activity

### SOC Reality
- Incidents—not alerts—drive response actions
- This is the level at which containment, eradication, and recovery occur

---

## Key Takeaway

- **Alerts** generate noise
- **Detections** generate confidence
- **Incidents** generate action

A mature SOC focuses on reducing alert fatigue, improving detection quality, and responding decisively to real incidents.
