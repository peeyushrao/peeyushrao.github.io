# CrowdStrike Multipurpose Queries

## Network Containment Visibility Queries

These queries help identify:
- Which hosts were network contained
- Which Falcon admin initiated or lifted containment
- Source IP of the admin action
- Hostnames associated with containment activity

---

# Query 1 — Hosts That Were Network Contained

```sql
#event_simpleName=NetworkContainmentCompleted
| table([@timestamp, ComputerName, UserName, aid])
```

## Purpose

Displays endpoints that successfully entered network containment.

This query is useful for:
- Incident response validation
- Tracking containment activity
- Confirming hosts were isolated
- Building containment reports

---

## Field Explanation

| Field | Description |
|---|---|
| `@timestamp` | Time containment completed |
| `ComputerName` | Hostname of the endpoint |
| `UserName` | Logged-in user on the endpoint |
| `aid` | Falcon Agent ID (unique host identifier) |

---

## Important Notes

This is a sensor event generated by the endpoint.

It tells you:
- A host was contained

It does NOT tell you:
- Which Falcon admin initiated containment

For admin attribution, use Query 2.

---

# Query 2 — Identify Which Falcon Admin Contained or Lifted a Host

```sql
#event_simpleName=Event_UserActivityAuditEvent
| OperationName=/containment_(requested|lifted)/i
| Action:=case {
    OperationName="containment_requested" | "Contained";
    OperationName="containment_lifted" | "Lifted";
}
| join(
    {
      #event_simpleName=/Network(Containment|Uncontainment)Completed/
      | table([aid, ComputerName])
    },
    field=agent.id,
    key=aid,
    include=[ComputerName]
  )
| table([@timestamp, Action, UserId, UserIp, ComputerName])
| sort(@timestamp, order=desc)
```

---

## Purpose

Displays:
- Falcon admin who initiated containment
- Falcon admin who lifted containment
- Source IP of the Falcon session
- Hostname affected

This query combines:
- Falcon audit logs
- Endpoint containment sensor events

---

## Field Explanation

| Field | Description |
|---|---|
| `@timestamp` | Time action occurred |
| `Action` | Contained or Lifted |
| `UserId` | Falcon user/admin account |
| `UserIp` | Source IP address of admin session |
| `ComputerName` | Endpoint hostname |

---

## How the Query Works

### Step 1 — Audit Events

```sql
#event_simpleName=Event_UserActivityAuditEvent
```

Searches Falcon administrative audit events.

---

### Step 2 — Filter Containment Actions

```sql
| OperationName=/containment_(requested|lifted)/i
```

Filters only:
- containment_requested
- containment_lifted

---

### Step 3 — Create Readable Action Names

```sql
| Action:=case {
    OperationName="containment_requested" | "Contained";
    OperationName="containment_lifted" | "Lifted";
}
```

Converts raw operation names into cleaner labels.

---

### Step 4 — Join Hostnames

```sql
| join(
    {
      #event_simpleName=/Network(Containment|Uncontainment)Completed/
      | table([aid, ComputerName])
    },
    field=agent.id,
    key=aid,
    include=[ComputerName]
  )
```

Maps:
- Falcon audit event `agent.id`
to
- endpoint sensor event `aid`

This enriches audit logs with endpoint hostnames.

---

### Step 5 — Display Final Results

```sql
| table([@timestamp, Action, UserId, UserIp, ComputerName])
```

Shows the final analyst-friendly output.
